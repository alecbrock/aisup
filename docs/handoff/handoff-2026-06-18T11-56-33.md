## Decisions Made

- **Usage ledger design (adopted from user).** Providers expose no uniform live-quota API (confirmed: claude/pilot have none; codex ChatGPT-auth has none; gemini none). So capture exact usage while a session is active + **decay each rolling window to 0% once its `reset_at` passes** + reactive 429 backstop. Tag windows `live|aged|reset|unknown` so the UI never shows stale numbers as current. **Rationale:** the only reliable signals are live-while-active usage, deterministic resets, and reactive errors. **Rejected:** trying to read remote quota per provider (doesn't exist); leaving stale telemetry as-is (the original bug).
- **Default runner = `claude`, not `pilot`.** Modern Pilot Shell is hook-integrated; `pilot` alone prints a banner and exits. **Rejected:** keeping `pilot` (non-functional) or `pilot <args>`.
- **F2 crash-loop fix: count every crash pass, clear only on genuine recovery (pane alive).** Previously `onRestart()` returning true cleared the counter even while flapping. **Rejected:** counting only failed restarts (the bug).
- **Worker validation uses real codex, same-model review** (`allow_same_model_review: true`) since only codex is installed. True cross-model review (PRD AC3) is deferred to Part B.
- **Part B scope (from user):** worker-only multi-provider failover; orchestrator stays Claude-account-only. Each role (implementer/reviewer) can be any provider/model; **failover priority = Claude accounts first, then other LLMs.** Per-provider usage = real reader where possible + configurable limit + reactive backstop (Claude = % via tap; codex = local consumption meter vs a budget). See Part B section of the active plan.

## Deviations / Workarounds (operational knowledge NOT in git)

- **Detached daemon gets reaped in an assistant Claude Code shell.** `aisup daemon start` detaches and is killed when the foreground bash call returns *in this harness*. For testing, start the daemon via a kept-alive background process: `Bash(run_in_background=true)` running `node dist/daemon/index.js`. **In a real terminal `aisup daemon start` works normally.**
- **Always `source ~/.aisup/secrets.env` before starting the daemon** for Slack tokens + `CODEX_HOME`. `~/.zshrc` already sources it, so a fresh login shell is fine; programmatic starts must source it.
- **No `--config`/`AISUP_CONFIG` override exists** (`loadConfig()` is hardcoded to `~/.aisup/config.yaml`). To test low thresholds / fake runner: **backup → edit → restore** `config.yaml` (and restart the daemon). Candidate enhancement: honor `AISUP_CONFIG`.

## Issues, Root Causes, and Fixes

1. **Daemon could never start** (FIXED `1d46673`). Root cause: `tsup.config.ts` only built `cli/index`, so `dist/daemon/index.js` (spawned by the launcher) didn't exist; `stdio:'ignore'` hid the `MODULE_NOT_FOUND`. Fix: add the daemon build entry.
2. **All authed CLI/daemon calls failed ("not responding"/401)** (FIXED). Root cause: `~/.aisup/api-token` only created by `aisup init` (which overwrites config); a hand-edited config left no token. Fix: generated a 32-byte hex token (0600). Candidate: daemon should self-generate if missing.
3. **Stale usage → wrong account selection** (FIXED `e0e5385`). Root cause: usage read straight from the statusline tap, which is only fresh while a session renders; idle accounts showed ~day-old data (e.g. `5h 100%` from a window that reset 23h earlier) presented as current. Fix: the usage ledger (decay-to-zero at reset + basis tags).
4. **F1 — default runner `pilot` can't start a session** (FIXED `d8c5e0c`). Root cause: pilot is hook-integrated now, exits immediately. Fix: default → `claude`.
5. **F2 — unbounded crash-restart loop** (FIXED `d8c5e0c`). Root cause: a launch-then-exit runner makes `onRestart()` return true, which cleared the restart counter every tick → infinite 5s loop, no breaker/alert. Fix: count every crash pass, clear only on pane-alive recovery, record a breaker failure + escalate at the cap.
