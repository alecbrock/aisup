## Decisions Made

- **`handleNoTarget` lives in `switcher.ts`, not loop-manager.** Rationale: cohesive with `performSwitch`'s exhaustion logic and unit-testable (daemon `onSwitch` is the untestable composition root). The plan listed loop-manager.test.ts/server.test.ts for R2 tests; I put the core test in switcher.test.ts (more natural home) plus loop-manager soft-no-target + server EXHAUSTED-visibility tests.
- **`onSwitch` reads `readState(sessionId)` instead of `getActiveSession()`.** Rationale: `getActiveSession()` only returns ACTIVE/SWITCH_PENDING_AT_IDLE, so it cannot recover a mid-switch SWITCHING session during rehydration. Reading by id works for both the loop-manager path and rehydration.
- **`scoreAccount` made synchronous.** Rationale: only sync I/O; lets `refreshAccountScores` be sync so it runs inside the synchronous `rateLimitTick` without making the tick async. No non-test callers existed.
- **`telemetry.invalid_json` emission deferred from R7 to R12.** Rationale: it requires refactoring the telemetry resolver, which R12 owns ("use the same resolver during rehydration"); doing it in R7 then re-touching in R12 would be duplicate work. Documented inline in the plan's R12 line.
- **R8 daemon-side poller re-arm left for Task 7.** `rehydrateSessions()` returns `exhaustedSessionIds`, but `daemon/index.ts` does not yet capture/re-arm them because `ExhaustedRecovery` (Task 7) does not exist. Task 7 wires the capture + re-arm.
