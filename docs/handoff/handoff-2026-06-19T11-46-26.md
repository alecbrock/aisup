## Decisions Made

- **Hooks, not regex-on-scraped-output, for J & F (user-chosen).** Claude Code 2.1.x stopped emitting the
  `Launching skill:` marker and renders permission prompts as cursor-positioned modals that garble in the
  pipe stream. Hooks give structured, version-stable, ~0-token signals. Verified the exact events + payloads
  live: **J = `UserPromptExpansion`** (`command_name`), **F = `PermissionRequest`** (`tool_name`+`tool_input`).
  **Rejected:** refreshing the regexes (still brittle); rendered-screen-snapshot (held in reserve).
- **F is NON-BLOCKING + keystroke resolution (user requirement: "permissions must NOT time out").** First
  built it as a blocking HTTP hook that returned allow/deny; that auto-denied at `grant_ttl` and, more
  fundamentally, hit Claude Code's hook-timeout cap (a 16-min wait killed the connection). Re-architected: the
  hook posts to Slack and returns `null` (defer to Claude's terminal dialog, which never times out); `!permit`/
  `!deny` later sends a keystroke (`approval_key`/`denial_key`, default `1`/`3`) to the persistent dialog.
  **Proven by a ~12-min gap that still succeeded.** **Rejected:** blocking hook with a long timeout (capped by
  Claude); the legacy scrape-broker (broken detection + TTL).
- **Install via `claude --settings ~/.aisup/claude-hooks.json`** (additive, 0600, literal bearer token),
  appended to `config.runner.args` once at daemon startup. **Rejected:** editing the user's account/repo
  settings (invasive). Skill hook always installed; permission hook only when `permissions.enabled`.
- **Error/recovery detection stays on flat-text scanning** (hooks can't catch crashes/429). Only J & F moved.
- **429 patterns tightened** to require error context (kept all real-error phrasings, rejected "add rate
  limiting", "wait 5 minutes for the build", "add a usage cap").

  self-test inbound).
