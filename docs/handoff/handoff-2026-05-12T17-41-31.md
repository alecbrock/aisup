## Key Context for Next Session

### Critical codebase knowledge discovered during review

1. **`active_skill` is sticky** — once set by `detectSkill()` in `recoveryTick()` (loop-manager.ts:268-277), it is never cleared to null. Only updated when a NEW skill is detected. The `SkillTracker` class (skills/tracker.ts) has a `reset()` method but loop-manager does not use SkillTracker — it calls `detectSkill()` directly.

2. **Rehydration is NOT detection-only** — `recoverSwitchTx()` in rehydration.ts already takes corrective actions for 3 of 6 switch phases. Pipe-pane restore already works (lines 183-193). Only state-without-tmux restart and completing switches for dead-target phases are genuinely new.

3. **`CONFIG_DEFAULTS` is typed `Omit<AisupConfig, 'accounts'>`** — any new section added to `AisupConfig` MUST have a matching entry in `src/config/defaults.ts` or TypeScript will not compile.

4. **`CircuitBreaker.getState()` auto-transitions** — OPEN to HALF_OPEN happens inside `getState()` when cooldown expires. No need to check `getCooldownEta()` separately for polling logic.

5. **`child_process.execFile` does not parse command strings** — commands like `"npx tsc --noEmit"` will ENOENT. Must use `spawn` with `shell: true` or `exec`.

6. **`RehydrationDeps` has no access to switch/restart callbacks** — rehydration runs before loop manager is created (daemon/index.ts:93 vs 289). Any recovery requiring onSwitch/onRestart needs architectural accommodation.
