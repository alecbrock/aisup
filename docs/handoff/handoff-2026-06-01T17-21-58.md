## Decisions Made

- **Smoke test spawns the daemon via `tsx`, not a build.** `tsx` forks the real daemon, so `health.pid !== child.pid` — the test asserts consistency against the daemon's own persisted `daemon.pid` file instead of the launcher pid. Avoids a build step (and ENOSPC risk).
- **Lifecycle cost snapshots use the last cached periodic cost**, not a fresh telemetry read at the boundary. This is the plan-sanctioned fallback ("falls back to the last periodic snapshot rather than silently omitting cost") and keeps the wiring simple. Documented in `loop-manager.ts`.
- **Stop/manual-failover snapshots live in `server.ts`** via injected `captureCostSnapshot`/`clearCostTracking` callbacks (per ME-003: "stop/failover live in server.ts"); automatic-switch snapshot lives in `index.ts onSwitch`. Slack `!stop` (out of Task 3 file scope) is not separately wired → falls back to last periodic snapshot (documented).
- **Cost delta filtering tracks `emitted` (baseline) and `observed` separately** so sub-cent upward moves accumulate and lifecycle snapshots can emit the latest observed value.
- **Task 2 needed no production change** — R4/R8/R11/R12 already delivered it; only an orphan-reporting test gap was filled (verify-and-fill, not rebuild, per the prior handoff's guidance).
- **`aisup cost` permission/window output:** default = rolling windows (online `/api/cost` parity when daemon up); `--since`/`--account` always computed offline against the same configured journal file.
