## Decisions Made

- **Decision:** Worker adapters are generic config-driven `execFile` subprocesses, not hardcoded Codex/Gemini/local wrappers.
  **Rationale:** Avoids inventing provider CLI flags and keeps command/args/prompt delivery operator-controlled.
  **Alternatives rejected:** Provider-specific command builders with assumed CLI syntax.

- **Decision:** Worker presets ship disabled by default.
  **Rationale:** The plan requires no accidental provider invocation and no invented provider configuration.
  **Alternatives rejected:** Auto-enabling detected provider CLIs.

- **Decision:** Review fails closed; parse failure cannot be configured to approve.
  **Rationale:** A malformed reviewer response is not a safe merge signal.
  **Alternatives rejected:** A `parse_failure_verdict` or `require_cross_model` compatibility knob.

- **Decision:** Merge is only a working-tree `git apply` after explicit approval and patch hash re-verification.
  **Rationale:** aisup must not auto-commit, push, branch, or merge without user control, and reviewed bytes must match applied bytes.
  **Alternatives rejected:** Applying directly from a live worktree, auto-committing, or reusing approval after conflict/hash drift.

- **Decision:** The enforceable security boundary is structural diff scoping plus workspace/forbidden-path audit, with isolated HOME for trusted CLIs.
  **Rationale:** This guarantees only the worktree diff can reach the main workspace while documenting the Phase 3 residual risk for arbitrary absolute writes outside the workspace.
  **Alternatives rejected:** Claiming full OS sandboxing in Phase 3; `sandbox-exec` remains deferred hardening.

- **Decision:** Real provider CLI tests are host-gated and skipped by default; deterministic smoke tests use fake `node -e` adapters against real temp git repos.
  **Rationale:** CI should stay green without provider CLIs while still proving the worker orchestration pipeline end to end.
  **Alternatives rejected:** Mandatory provider CLI tests or purely mocked integration tests.

- **Decision:** Slack worker approval uses `!worker ...` subcommands.
  **Rationale:** Keeps bare `!deny` reserved for permission denial and avoids overloading existing Slack control semantics.
  **Alternatives rejected:** Reusing bare `!approve`/`!deny` for worker patches.
